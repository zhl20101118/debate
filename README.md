# AI 辩论室 · 四对四标准赛制

八位 AI 辩手分列正反两方，按**四对四标准赛制**实时对线；全程可暂停、单步、撤回，结束后自动生成裁判裁定与带出处的复盘报告。

零依赖：只用 Node 内置模块，不需要 `npm install`。

---

## 快速开始

```bash
cd D:/noip/debate
node server.js          # 或双击 start.bat
```

- 本机：`http://localhost:8787`
- 局域网：终端会打印类似 `http://172.16.10.18:8787` 的地址，手机/平板可直接观看
- 第一次使用：右上角 ⚙ → 填 DeepSeek API Key（只写本机 `data/secrets.json`，不入库）
- 想限制"只能看不能控"：`ADMIN_TOKEN=xxx node server.js`

环境变量：

| 变量 | 作用 |
|---|---|
| `DEEPSEEK_API_KEY` | 优先于本地文件里的 Key |
| `ADMIN_TOKEN` | 设置后，控制类接口需要口令 |
| `PORT` / `HOST` | 默认 `8787` / `0.0.0.0` |
| `DEBATE_MOCK=1` | 离线演练：不调用 API，用假数据跑完整流程（用于调试界面） |

## 赛制

标准四对四赛制，18 个环节、约 30 分钟，环节表与实际执行同源（改配置会自动同步到提示词）：

| # | 环节 | 时长 |
|---|---|---|
| 1–2 | 正方一辩 / 反方一辩 立论 | 3:00 |
| 3–4 | 正方二辩 / 反方二辩 驳论 | 2:00 |
| 5–8 | 正三质询 → 反三应答 → 反三质询 → 正三应答 | 1:30 / 2:00 |
| 9–10 | 正方一辩 / 反方一辩 质询小结 | 1:30 |
| 11–16 | 自由辩论 3 轮，正反交替 | 1:00 / 段 |
| 17–18 | 反方四辩 / 正方四辩 总结 | 3:30 |

字数是照真人语速折算的（默认 240 字/分钟）：3 分钟 720 字、2 分钟 480 字、质询 360 字，与真人辩论的信息量对齐。

## 缓存：怎么做到"越打越省"

DeepSeek 用的是**前缀缓存**：两次请求只要 messages 开头逐字节一致，这段前缀就按缓存价计费（约为未命中的 1/10）。

所以本项目把整场辩论组织成**一段只追加、不改写**的多轮对话：

```
[0] system    全局铁律                     ← 整场恒定
[1] user      本场简报                      ← 整场恒定
              辩题 / 赛制表 / 七类环节写法 / 八人档案 / 资料库 / 跨场记忆
[2] user      第 1 回合任务
[3] assistant 第 1 回合发言原文
[4] user      第 2 回合任务
[5] assistant 第 2 回合发言原文
...
```

第 n 次请求的 messages 是第 n−1 次的**严格超集**，命中量单调增长；真正按原价计费的只有「上一段发言 + 本轮任务」。

几个关键设计：

- **七类环节的写法要求放进恒定简报**，任务里只说"按第 3 条执行"，每轮少 200 token 未命中。
- **八人档案全部在恒定前缀里**，本轮只点名出场者，不重复人格。
- **裁判、报告、赛后复盘复用同一段前缀**，这三步几乎全命中。
- **一场只用一个模型**（chat 与 reasoner 的缓存不互通，混用会各打各的）。
- 删掉了"你方已确立论点""对方最近发言"这类在实录里本就存在的重复段落。

实测（`deepseek-chat`，12 次连续调用，含资料库）：

```
第 2 次  83.5%      第 8 次  93.3%
第 5 次  87.8%      第12 次  92.8%
累计：命中 54400 / 未命中 9698 → 84.87%
```

`deepseek-reasoner` 同样命中（第 2 次 61%，第 5 次 74.5%，随前缀增长继续上升）。

**为什么累计到不了 98%：**命中率 ≈ 1 − 新增/总 prompt，而"新增"就是上一段发言本身 —— 它必须回传。18 轮 700 字的比赛，末轮前缀约 12k token，新增约 700 token，单次上限约 94%；要把累计推到 98%，前缀得堆到 4 万 token 以上，等于多付钱买一个好看的数字。界面里同时显示**累计命中率**和**上一次命中率**，后者在比赛中后段稳定在 90%+，才是真实体感。

## 实时能看到什么

- 发言 **逐字流式**（服务端把 token 合批成 70ms 一帧，避免刷爆浏览器）
- **思考过程默认折叠**，折叠状态下 summary 里滚动显示"正在想什么"的最后一句；点开可看完整思考链
- 右侧「实时状态」：当前发言人、计时器、输出字数/目标、思考字数、模型
- 右侧「流程进度」：18 个环节的时间轴，当前环节高亮，**点击任意环节跳到那段发言**；滚动实录时会反向高亮
- 断线重连/刷新不丢画面：服务端保留半成品，快照会补回来

控制条：开始 / 暂停 / 单步 / 跳过环节 / 撤回上一轮 / 结束 / 主席留言（临时干预下一位发言者）。

## 跨场记忆与系列赛

- 每场结束后，会用**一次**调用让"复盘教练"给八位辩手各写一条迭代笔记（保持什么、改进什么、下一场第一句怎么说），写入 `data/memory/<side>-<id>.json`
- 下一场开场前，这些笔记进入恒定简报，辩手带着经验上场；默认保留最近 **4 场**
- `系列赛场数` 默认 4：一场打完自动开下一场，记忆累积，辩手逐场变强
- 设置里可清空记忆重来

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| GET/POST | `/api/config` | 读写设置 |
| GET/POST/DELETE | `/api/secrets` | Key 状态 / 写入 / 清除 |
| GET/POST | `/api/sessions` | 列表 / 新建（`autoStart` 直接开跑） |
| GET/DELETE | `/api/sessions/:id` | 单场详情 / 删除 |
| GET | `/api/sessions/:id/stream` | SSE：snapshot / turn_start / delta / tick / turn_done / judge_delta / report_done … |
| POST | `/api/sessions/:id/control` | `start` `pause` `step` `skip` `rewind` `inject` `stop` `conclude` `regenerate-report` |
| GET | `/api/sessions/:id/report` | 报告（`?download=1`） |
| GET | `/api/sessions/:id/export` | 全程实录（含思考过程） |
| GET/DELETE | `/api/memory` | 跨场记忆列表 / 清空 |
